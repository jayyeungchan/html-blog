oxlint 规则地图：808 条规则，默认只开 111 条

oxlint 跑起来是真的快，快到你会忘记它是个 linter。装完第一件事是跑一遍，第二件事是想弄清楚它到底在查什么，然后就卡住了：npx oxlint --rules 吐出来 871 行纯文本，规则名一行一个，默认开没开、能不能自动修、出了事是什么后果，全得自己猜。

官方文档是按插件分的，eslint 一栏、react 一栏、typescript 一栏。这种分法回答的是「这条规则谁写的」，我关心的是另一个问题：它防的是什么事故。两个问题的答案经常不在同一页上。

所以我把这 871 行抓下来，去重、归类，给每条配一段反例，默认开启的那 111 条再逐条写中文说明，做成了一张能搜的图。文末有入口，也可以直接打开规则地图。

871 行不是 871 条

同一个规则名会在不同插件下各实现一次。no-dupe-keys eslint 有，vue 也有；jest 和 vitest 那一批 no-focused-tests、expect-expect 更是成对出现。按名字去重，62 个名字重复，多出 63 行，剩下 808 条。

这 808 条里，默认开启 111 条，能自动修 214 条，分成 7 个类别：

类别条数默认开启
correctness260111
style2370
pedantic1210
restriction1030
suspicious620
perf150
nursery100

111 除以 808 是 13.7%。装完 oxlint 直接跑，它只用不到七分之一的规则在看你。

默认只开「确定是 bug」那一类

111 条全落在 correctness，一条不漏。suspicious 默认一条都没开，这一类是「看起来像写错了」，很可能有问题，但也会误报，oxlint 干脆不放进默认集。

我一开始嫌它保守，用久了觉得合理。默认集一旦带上误报，第一次跑就是几十条红字，人的第一反应不是去修，是把 linter 关掉。宁可不查，也别让人失去耐心。

代价也很实在。style 那 237 条、pedantic 那 121 条全都得自己挑，而挑的时候你面对的是八百多个英文名字。这正是做这张地图的原因。

按事故分组，比按插件分组有用

地图里我没沿用插件的分法。勾上「只看默认开启」，那 111 条会按「它在防什么事故」分成 12 组：变量赋值写错、写了没用、条件与比较、重复定义、数组与集合、Promise 与异步、TypeScript 类型、类与继承、正则与字符串、错误处理、危险 API、其他零散。

同一个组里的规则常常来自不同插件，踩的却是同一个坑。异步那一组里，no-async-promise-executor 是 eslint 的，no-floating-promises 是 typescript 的，按插件查得翻两个页面，按事故查它们就挨着。

808 段反例，111 句中文

反例是全覆盖的。808 条每条都配了一段真会出事的代码，这也是最费工的部分。反例编得太假，读者一眼就知道这条跟自己无关，那这条就白写了。

no-cond-assign 的说明是「if / while 的条件里写了赋值，= 写成 == 的经典事故」，反例长这样：

let found;
if (found = search()) {  // ✗ = 写成了 ==
  use(found);
}

no-async-promise-executor 更隐蔽一点：

new Promise(async (resolve) => {  // ✗ 抛出的错误会被吞掉
  await load();
  resolve();
});

两段代码看一眼就懂，比读十条英文文档快。但中文说明我只写了默认开启的那 111 条。理由很实际：这 111 条装完就会撞上，值得逐条讲清楚；剩下 697 条得自己主动开，等真开了再去翻文档也不迟。硬凑 808 句，多半会写出「禁止使用某些特性」这种谁看都没用的废话。

一个 HTML 文件，没有后端

整张地图就是一个 HTML 文件，160KB，双击能打开，搜索在本地跑，不联网。数据压成一行字符串塞在 <script> 里，每条五个字段：

no-cond-assign~eslint~cor~1~0

规则名、插件、类别、默认开、能不能修，用 ~ 隔开，条与条之间用 ;。808 条加起来 31KB，比 JSON 省一大截，也省掉了构建这一步。改数据就是改这一行字符串。

界面只有三个开关：只看默认开启、只看可自动修复、显示反例，再加一个搜索框。够用了。

怎么用

  1. 先跑 npx oxlint，把默认集报出来的问题清掉。默认集一共 111 条规则，实际报的通常没几条，但报出来的基本都是真 bug。
  2. 再跑 npx oxlint --fix。214 条可自动修的规则里，能修的它自己修，剩下的才需要人看。
  3. 想加规则，从 12 组里挑最近真踩过的坑，一次三到五条。别一口气开一百条，第二天你就会把它从 CI 里删掉。

还有一句提醒：地图是 1.89.0 的快照，版本一更新规则就会变。真要长期用，以 npx oxlint --rules 的输出为准，地图用来理解，别拿来当配置清单抄。
