静态博客是怎么跑起来的

这套博客只有三层：目录是数据结构，HTML 文件是内容，一份 JSON 是索引。没有数据库，也没有后台，首页之所以知道有哪些文章，全靠构建时扫了一遍文件夹。

目录结构就是数据结构

仓库长这样：

.
├── index.html              # 首页
├── build.js                # 构建：扫描 → 生成索引
├── articles.json           # 构建产物
├── assets/                 # 样式、脚本、图标
├── _templates/article.html # 新文章模板（下划线开头，不参与扫描）
├── 技术/
│   ├── 为什么这个博客不用框架.html
│   └── 静态博客是怎么跑起来的.html
├── 生活/
│   └── 我的2026阅读清单.html
└── 随笔/
    └── 关于慢下来.html

一级目录就是分类，目录里的 HTML 就是文章，文件名就是标题（如果 <title> 存在则优先用 <title>）。想加一个「读书笔记」分类？新建一个文件夹就行。

build.js 只做一次翻译

构建脚本做的事情非常单调：递归遍历目录，跳过 assets、_templates 和下划线开头的文件，然后从每个 HTML 里读出四件事——标题、摘要、日期、标签。

<meta name="description" content="一句话摘要，会出现在首页列表里。" />
<meta name="date" content="2026-10-18" />
<meta name="tags" content="静态站点,Render" />

日期没写的话，会退回到文件的修改时间，所以哪怕完全不管元数据，文章也不会从列表里消失。阅读时长由正文字数估算，中文按 350 字每分钟。

输出只有两个文件：articles.json 给页面读，sitemap.xml 给搜索引擎读。

首页怎么知道有哪些文章

首页加载后请求 articles.json，拿到全部文章的标题、地址、分类、日期、摘要、标签，然后渲染分类卡片和列表。搜索和筛选都发生在这份数组上，不产生任何请求，所以是即时的。

请求时加了时间戳并禁用缓存，避免部署后仍然看到旧的列表。这是纯静态站点最容易踩的坑：内容更新了，浏览器还拿着上一份 JSON。

为什么不用前端路由

因为文件系统已经把路由做好了。每篇文章都是一个真实存在的地址，可以被收藏、被分享、被搜索引擎直接索引，也可以在没有 JS 的情况下正常阅读——只有顶栏和目录是脚本注入的。

这一点在弱网和移动端尤其明显：正文是首屏 HTML 的一部分，不需要等 JS 执行完才出现。

新增一篇文章的完整流程

  1. 复制 _templates/article.html 到目标分类目录，命名成文章标题
  2. 改四个 meta：title、description、date、tags
  3. 在 <article class="prose"> 里写正文
  4. git push

Render 收到推送会自动执行构建并发布，首页列表随之更新。整个过程不需要登录后台，也不需要手动触发部署。

部署到 Render

仓库里带了 render.yaml，在 Render 里选择 Blueprint 指向这个仓库即可。手动配置的话只有三项：

配置项值
EnvironmentStatic Site
Build Commandnode build.js
Publish Directory.

因为发布目录就是仓库根目录，所以不需要任何复制或打包步骤，构建只是重新生成索引，通常一两秒结束。
