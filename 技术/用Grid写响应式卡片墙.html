用 Grid 写一张响应式卡片墙

首页的分类卡片墙，从手机到宽屏只用了两行 CSS，没有写任何媒体查询。核心是这一句：

.cat-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(210px, 1fr));
  gap: 0.875rem;
}

auto-fill 与 minmax 的分工

minmax(210px, 1fr) 说的是「每列至少 210px，剩余空间平分」。auto-fill 说「在容器里塞尽可能多的列」。两者合起来，浏览器会在每次布局时自己算出该有几列。

对比一下 auto-fit：它会把空轨道折叠掉，让卡片在数量少时被拉得很宽。auto-fill 则保留空位，卡片宽度稳定。对卡片墙来说，稳定的宽度通常更好看。

如果一个布局规则需要三条以上的媒体查询来维持，先怀疑是不是用了固定宽度。

断点不是越多越好

自动列数解决了「几列」的问题，但解决不了「内容密度」。手机上两个 210px 的卡片并排会挤到无法阅读，所以仍然需要一个断点，把间距和字号收一收：

@media (max-width: 720px) {
  .cat-grid {
    grid-template-columns: 1fr 1fr;
    gap: 0.6rem;
  }
  .cat-card { padding: 0.95rem 1rem; }
  .cat-card p { display: none; }
}

注意最后一行：小屏直接隐藏描述文字，而不是让它压成三行。移动端不是「把所有内容缩小」，而是「决定哪些内容此刻不重要」。

让卡片有呼吸

三个细节决定卡片看起来是「设计过的」还是「堆出来的」：

  • 内边距比外边距大一点，卡片内部才有空气感
  • 悬停时只动 2–3px，配合 300ms 缓动，动作要小到几乎察觉不到
  • 用 transform 而不是 top 做位移，避免触发重排

底部的强调线用 transform: scaleX() 从 0 拉到 1，比改宽度便宜得多，也更容易做得顺滑。

什么时候该放弃自动布局

当卡片的视觉重量差别很大时——比如一张大图配三张小卡——自动列数会强行把她们排成一样宽。这种「编辑式布局」还是老老实实用 grid-template-areas 手写，可读性反而更高。
